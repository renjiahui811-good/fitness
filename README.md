# 训练与康复记录

一个单文件的打卡页面。11/2 – 11/29 在家早晨训练 4 周(周三休息、周日网球)、饮食手掌法打卡、体重曲线到 12/31,数据存在浏览器本地。

## 发布到 GitHub Pages

1. 在 GitHub 新建仓库,取个名字,比如 `fitness`。**Public**(私有仓库的 Pages 需要付费账户)。
2. 把 `index.html` 和 `README.md` 上传进去(网页上直接 Add file → Upload files 就行,不用装 git)。
3. 仓库 Settings → Pages → Source 选 **Deploy from a branch**,分支选 `main`,目录选 `/ (root)`,Save。
4. 等 1–3 分钟,页面顶部会出现地址:`https://你的用户名.github.io/fitness/`

## 手机上使用

用 Chrome 或 Safari 打开上面那个地址,然后:

- **Android Chrome**:右上角 ⋮ → 添加到主屏幕
- **iPhone Safari**:底部分享按钮 → 添加到主屏幕

之后从主屏图标打开,跟 App 一样,没有地址栏。

## 数据存在哪

存在你手机浏览器里,绑定在 `你的用户名.github.io` 这个域名上。只要地址不变、不清缓存,数据就一直在。

**会丢的两种情况**:清除浏览器数据、换手机。所以:

> 每月导出一次备份。页面底部「备份数据」→ 导出 → 自动复制 → 粘贴到备忘录或微信收藏。
> 换设备时把那段文字粘回去点导入即可恢复。
> 超过 14 天没备份,「备份数据」旁边会出现橙色提醒。

## 修改内容

所有计划、动作、要点都写在 `index.html` 的 `<script>` 里:

- `START` / `GYM` / `GOAL_DATE` / `W_START` / `W_GOAL` — 起止日期和体重目标(参考线 91 → 85)
- `WEEKS` — 每周的组数、跳操时长、循环轮数
- `WEEK_TPL` — 一周七天的安排(周一 A、周二跳操、周三休、周四 B、周五跳操、周六 C、周日网球)
- `LIFTS` / `CIRCUIT` — A、B 的动作,C 的循环动作
- `WARM` / `CORE` — 热身(每天一样,含康复)、跳操日的核心
- `COOLS` — 按当天类型(A / B / C / 跳操)配的拉伸,每项写明拉哪里、对应哪个动作
- `LIGHT` — 身体不适跳过时的轻松版
- `TENNIS_WARM` / `TENNIS_COOL` — 周日网球的球前热身和球后拉伸
- `VIDEOS` — 跳操视频(YouTube,Move To The Beat 系列)
- `EX` — 动作库:默认量、要点、图片、示范搜索词
- `FIG` — 手绘示意图(SVG),用于图库里没有的动作

动作动图在 `img/`,由 [free-exercise-db](https://github.com/yuhonas/free-exercise-db)(公共领域)的起止两帧照片合成。

健身房阶段从 11/30 开始,到时在 `WEEKS` 里加新周、调整 `WEEK_TPL` 即可。

## 医疗提醒

本页面依据 2025-10-09 的 MRI 报告(腰5椎体Ⅰ度滑脱、腰5-骶1椎间盘膨出、颈3-4轻度突出、颈椎生理曲度变直)与右膝情况设计,避开了屈伸腰、轴向大负荷、跑跳类动作。

出现腿麻、脚无力、下肢放射痛、手指麻木 → 停止训练并就医。
